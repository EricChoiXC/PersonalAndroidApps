# Android 开发规范

> 来源：https://cloud.tencent.com/developer/article/2501461（转自掘金，原作者 Blankj）
> 原文：https://github.com/Blankj/AndroidStandardDevelop

## 1 前言

为了有利于项目维护、增强代码可读性、提升 Code Review 效率以及规范团队安卓开发，故提出以下安卓开发规范。

## 2 AS 规范

1. 尽量使用最新的稳定版的 IDE 进行开发；
2. 编码格式统一为 **UTF-8**；
3. 编辑完 .java、.xml 等文件后一定要 **格式化**；
4. 删除多余的 import，减少警告出现，利用 AS 的 Optimize Imports 快捷键；
5. Android 开发者工具可以参考 Android 开发者工具。

## 3 命名规范

代码中的命名严禁使用拼音与英文混合的方式，更不允许直接使用中文的方式。

> 注意：即使纯拼音命名方式也要避免采用。但 `alibaba`、`taobao`、`youku`、`hangzhou` 等国际通用的名称，可视同英文。

### 3.1 包名

包名全部小写，连续的单词只是简单地连接起来，不使用下划线，采用反域名命名规则，全部使用小写字母。

所有项目的包名根路径统一为 `com.ericxc.android.${projectName}`，其中 `${projectName}` 使用项目目录名的小写字母形式。各项目的 `namespace`、`applicationId`、源码包声明和源码目录路径必须保持一致。

推荐采用 PBF（按功能分包 Package By Feature），而不是 PBL（按层分包 Package By Layer）。PBF 优势：

- package 内高内聚，package 间低耦合
- package 有私有作用域
- 很容易删除功能
- 高度抽象
- 只通过 class 来分离逻辑代码
- package 的大小有意义了（包太大表示需要重构）

按功能分包示例：

```
com
└── domain
    └── app
        ├── App.java              # Application 类
        ├── Config.java           # 配置数据（常量）
        ├── base                  # 基础组件
        ├── custom_view           # 自定义视图
        ├── data                  # 数据处理
        │   ├── DataManager.java  # 数据管理器
        │   ├── local             # 本地数据（SP, Database, File）
        │   ├── model             # Model 定义
        │   └── remote            # 远端数据
        ├── feature               # 功能
        │   ├── feature0          # 功能 0
        │   └── ...               # 其他功能
        ├── injection             # 依赖注入
        ├── util                  # 工具类
        └── widget                # 小部件
```

### 3.2 类名

类名以 `UpperCamelCase`（大驼峰）风格编写。

| 类 | 描述 | 例如 |
|---|---|---|
| Activity 类 | Activity 为后缀 | WelcomeActivity |
| Adapter 类 | Adapter 为后缀 | NewsDetailAdapter |
| 解析类 | Parser 为后缀 | HomePosterParser |
| 工具方法类 | Utils 或 Manager 为后缀 | ThreadPoolManager, LogUtils |
| 数据库类 | DBHelper 为后缀 | NewsDBHelper |
| Service 类 | Service 为后缀 | TimeService |
| BroadcastReceiver 类 | Receiver 为后缀 | JPushReceiver |
| ContentProvider 类 | Provider 为后缀 | ShareProvider |
| 基础类 | Base 开头 | BaseActivity, BaseFragment |
| 测试类 | 被测类名 + Test | HashTest |

接口命名规则与类一样采用大驼峰命名法，多以 able 或 ible 结尾。如果项目采用 MVP，所有 Model、View、Presenter 的接口都以 I 为前缀。

### 3.3 方法名

方法名以 `lowerCamelCase`（小驼峰）风格编写。

| 方法 | 说明 |
|---|---|
| initXX() | 初始化相关方法 |
| isXX(), checkXX() | 返回 boolean 型的方法 |
| getXX() | 返回某个值 |
| setXX() | 设置某个属性值 |
| handleXX(), processXX() | 对数据进行处理 |
| displayXX(), showXX() | 弹出提示框和提示信息 |
| updateXX() | 更新数据 |
| saveXX(), insertXX() | 保存或插入数据 |
| resetXX() | 重置数据 |
| clearXX() | 清除数据 |
| removeXX(), deleteXX() | 移除数据或者视图 |
| drawXX() | 绘制数据或效果 |

### 3.4 常量名

常量名命名模式为 `CONSTANT_CASE`，全部字母大写，用下划线分隔单词。

### 3.5 非常量字段名

基本结构：`scope{Type0}VariableName{Type1}`

- **scope（范围）**：非公有、非静态字段以 `m` 开头；静态字段以 `s` 开头；其他以小写字母开头。
- **Type0（控件类型）**：UI 控件成员变量加上控件缩写作为前缀，如 `mIvAvatar`、`rvBooks`、`flContainer`。
- **VariableName（变量名）**：可使用量词，如 `mFirstBook`、`mPreBook`、`curBook`。
- **Type1（数据类型）**：集合添加 List、Map、Set 后缀，数组添加 Arr 后缀，如 `mIvAvatarList`、`userArr`。

### 3.6 参数名 / 3.7 局部变量名 / 3.8 临时变量

参数名和局部变量名以 `lowerCamelCase` 风格编写，避免用单个字符命名（临时变量和循环变量除外）。

### 3.9 类型变量名

单个大写字母（如 E, T, X）或以类命名方式加大写 T（如 RequestT）。

## 4 代码样式规范

### 4.1 使用标准大括号样式

左大括号不单独占一行，与其前面的代码位于同一行。条件语句需要添加大括号。

### 4.2 编写简短方法

尽量编写短小精炼的方法，如果方法代码超出 40 行，考虑拆解。

### 4.3 类成员的顺序

1. 常量
2. 字段
3. 构造函数
4. 重写函数和回调
5. 公有函数
6. 私有函数
7. 内部类或接口

若继承 Activity 或 Fragment，重写函数按生命周期排序（onCreate -> onResume -> onPause -> onDestroy）。

### 4.4 函数参数的排序

`Context` 作为第一个参数，回调接口作为最后一个参数。

### 4.5 字符串常量的命名和值

| 类 | 字段名前缀 |
|---|---|
| SharedPreferences | PREF_ |
| Bundle | BUNDLE_ |
| Fragment Arguments | ARGUMENT_ |
| Intent Extra | EXTRA_ |
| Intent Action | ACTION_ |

### 4.6 Activities 和 Fragments 的传参

提供 `public static` 的函数来帮助启动或创建 Activity/Fragment（使用 AS 的 starter / newInstance 模板）。

### 4.7 行长限制

代码中每一行文本的长度不超过 100 个字符。换行策略：

- 除赋值操作符外，换行符放在操作符之前
- 函数链的换行符插入在 `.` 之前
- 多参数在每个 `,` 后面换行
- RxJava 链式每个操作符换新行，换行符插入在 `.` 之前

## 5 资源文件规范

资源文件命名为全部小写，采用下划线命名法。

### 5.1 动画资源文件（anim/ 和 animator/）

命名规则：`{模块名_}逻辑名称`，如 `refresh_progress.xml`。

### 5.2 颜色资源文件（color/）

命名规则：`类型{_模块名}_逻辑名称`，如 `sel_btn_font.xml`。

### 5.3 图片资源文件（drawable/ 和 mipmap/）

`res/mipmap/` 只用于存放启动图标，其余图片资源文件都放到 `res/drawable/` 目录下。

命名规则：`类型{_模块名}_逻辑名称`，如 `btn_main_about.png`、`ic_edit.png`、`bg_main.png`。

### 5.4 布局资源文件（layout/）

命名规则：`类型_模块名`，如 `activity_main.xml`、`fragment_music.xml`、`dialog_loading.xml`、`item_main_song.xml`。

### 5.5 菜单资源文件（menu/）

命名规则：`{模块名_}逻辑名称`，如 `main_drawer.xml`。

### 5.6 values 资源文件（values/）

- **colors.xml**：映射颜色名称到 ARGB 值，使用语义化命名如 `white`、`gray_light`、`brand_primary`。
- **dimens.xml**：定义字体大小和间距的"调色板"，如 `font_18`、`spacing_24`。
- **strings.xml**：命名规则 `{模块名_}逻辑名称`，如 `main_menu_about`、`dialog_title`。
- **styles.xml**：name 使用大驼峰命名法。

### 5.7 id 命名

命名规则：`view 缩写{_模块名}_逻辑名`，如 `btn_main_search`、`btn_back`。

## 6 版本统一规范

统一管理 `compileSdkVersion`、`minSdkVersion`、`targetSdkVersion` 以及项目依赖第三方库的版本。

## 7 第三方库规范

选取稳定的、作者活跃维护的开源库，并进行必要的封装。推荐：

- Retrofit
- RxAndroid
- OkHttp
- Glide / Fresco
- Gson / Fastjson
- EventBus / AndroidEventBus
- GreenDao
- Dagger2（选用）
- Tinker（选用）

## 8 注释规范

### 8.1 类注释

每个类包含作者、联系方式、时间和描述。

### 8.2 方法注释

每个成员方法使用 Javadoc 格式注释。

### 8.3 块注释

使用 `/* ... */` 或 `// ...` 风格。

### 8.4 其他注释

使用 `TODO` 和 `FIXME` 标记待办和待修复项。

## 9 测试规范

- 测试类名：被测类名 + Test
- 测试函数名：以被测试方法为前缀，如 `signInWithEmptyEmailFails()`
- 单元测试通过且代码覆盖率达到约定标准后再提测

## 10 其他规范

- 合理运用 `<merge>`、`<ViewStub>`、`<include>` 标签
- 提供 BaseActivity 和 BaseFragment 基类
- 方法按调用先后顺序排列
- 数据提供统一入口（如 DataManager）
- 多用组合，少用继承
- 提取方法，去除重复代码
- 尽可能使用局部变量
- 及时关闭流
- 尽量减少对变量的重复计算
- 采用懒加载策略
- 不要在循环中使用 try-catch
- 使用带缓冲的输入输出流进行 IO 操作
- 使用 HashMap、ArrayList、StringBuilder（非线程安全场景）
- 使用 AS 自带的 Lint 优化代码结构
- 注意内存泄漏检测
